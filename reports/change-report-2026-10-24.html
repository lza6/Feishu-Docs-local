变更报告 · Feishu Docs Local

把"少导了内容"从静默失败，改成必须被看见

v1.1.0 只做一件事：让导出结果的完整性可以被验证。此前工具能跑、产物好看，但未支持的块会凭空消失，而 manifest.json 仍然报一个漂亮的块数——这不是 bug，是误导。

日期 2026-10-24 基线 a7f235f 版本 1.0.0 → 1.1.0 测试 39 + 11 全绿 真实导出 3 次（含 190MB 附件）
01 — 上下文

为什么要做这次变更

这个工具把飞书文档导成离线 HTML + Markdown。它能跑通，也在两份真实文档上验证过。但仓库里的改进指南记了一条 P0：

P0-1 · lib/render.mjs 的 switch 落在 default 且块既无 text 又无 children 时直接返回空字符串。视频、电子表格、多维表格、思维导图全部静默消失；而 manifest.blockCount 统计的是输入块总数，不是渲染成功的块数。

对用户来说，这意味着：你以为拿到了全文，实际缺了一章；而工具给你的"证据文件"反而证明了它很完整。这比崩溃更糟——崩溃至少你知道出事了。

同一批还挂着 8 个 P1：进程挂起 180 秒、missing 字段恒空、单块异常炸整篇、资源回传 O(n²)、分页静默截断、Node 版本声明不符、核心模块零测试。

02 — 判断

为什么先修这些，而不是先做界面

本轮原本的主攻方向是"本地 Web 工作台"。我把它顺延了，理由是：

  • 一条命令能导出，产品就已经可用；但会静默丢内容，产品就不可信。
  • 给一个会丢数据的东西做漂亮界面，等于把缺陷包装得更难发现。
  • P0/P1 全在纯 Node 层，与前端选型解耦——先修它们不产生返工。

这个取舍我写进了 workflow_status.md 的 Task Contract，没有静默跳过，也没有假装 GUI 已完成。

03 — 改动

做了什么

1 · 未支持的块必须留下痕迹

渲染器现在维护三条独立记录：unsupported（无内容可渲染）、degraded（有文本但类型未专门支持）、renderErrors（渲染抛异常）。三者都会在正文留下显式占位：

<div class="unsupported" data-type="media" data-token="…">［未支持块：media］</div>
<div class="render-error" data-type="code">［渲染失败块：code / blockId］</div>

Markdown 侧同样输出 > ［未支持块：media］。HTML 与 Markdown 两条路径各自有 try/catch，按块 id 去重记录——单块出问题只影响它自己。

2 · manifest 不再用单一数字暗示完整

字段含义实测值（真实文档）
blockCount接口返回的输入块总数45
renderedBlocks真正渲染出内容的块数26
unsupportedTypes未支持块类型分布{}
assets.saved / missing / skipped成功 / 失败 / 超限跳过，三者互斥12 / 0 / 1
truncated / pagesFetched分页是否被截断false / 1

renderedBlocks 明显小于 blockCount 是正常的（容器块、表格单元格都不产生独立内容），但两者并列就意味着：再也不能用一个数字假装内容完整。

3 · 三个修复里最隐蔽的一个

manifest.assets.missing 一直是 []。根因不在统计逻辑，而在参数语义：调用方传 [] 给 captureDoc，而代码只在 chunkIndexes === null 时返回资源清单 → probe.assets 恒为 undefined → missing 恒为空。

现在语义被拆清楚：null = 只探查（返回清单、不下载）、[] = 什么都不做、数组 = 下载指定批次，且清单始终返回。修完之后立刻抓到一个真实问题（见下）。

4 · 进程挂起与版本骗局

CDP.send 每次都注册一个 180 秒超时定时器，且从不清理、不 unref。导出日志已经打完，终端却要等定时器到期才返回。现在 unref() + settle/close 时 clearTimeout()。

engines.node 写的 >= 20，但代码直接用全局 WebSocket（Node 22 起稳定）。改成 >= 22，并在模块加载时探测——Node 20 会得到一句可执行的提示，而不是 ReferenceError。

5 · 顺带收口的边界

  • 资源分批只回传本批新增（原为全量重复回传，O(n²)）；单资源加体积上限。
  • 分页达到 200 页上限时标记 truncated，不再静默截断。
  • safeName('..') 不再能把产物写到 out/ 之外；输出目录额外做越界校验。
  • 参数缺值/非法以中文提示退出码 2，不再抛裸 TypeError。
  • 文件名处理 Windows 保留名与超长名；ZIP 容器按字节嗅探补 .zip。

过程中被打脸的一次

修完 P1-2 后第一次真实导出报 ⚠ 资源缺失 1 个，它此前永远显示 13/13。我第一反应是"我引入了回归"。

查下来缺失的是 RG-WorkSpace_V2.2_R1.5_Setup.zip——199,754,226 字节的单附件，被我新加的 128MB 安全阀拦住了。但它当时被记成 missing，而 skipped 是空的——因为 driver 只聚合了每批的 assetPayload，没聚合 skippedAssets，且每批都返回全量跳过项导致重复上报。

于是又修了两处：capture 只回传本批跳过项、driver 按 token 去重聚合，并把 missing 与 skipped 明确互斥。这件事恰好说明为什么这个修复值得做：旧版本并不是"没有缺失"，而是缺失被字段吞掉了。

05 — 风险与回滚

风险、回滚、能力边界

项说明
默认上限 128MB超过的单个附件从"能导出"变为"默认跳过"。这是有意的安全取舍（base64 回传会撑爆堆），可用 --max-asset-bytes 放开；已实测 190MB 在 2GB 堆下 30 秒完成。
--help 输出变化新增了完整选项段，属于信息增量而非破坏；已记录在 CHANGELOG。
engines.node 提升Node 20 用户会看到明确提示而非静默失败；如需继续用 20，加 --experimental-websocket。
回滚每项修复独立 commit，可逐个 git revert；整体回到 a7f235f 亦可。
06 — 边界

没做的事，以及为什么

  • 本地 Web 工作台（GUI）未实现：GET / 仍返回 503 与构建提示。服务端骨架已在，前端 ui/ 留待下一轮 S1。
  • sheet/bitable/mindnote 仍不导出内容：需要额外导出接口，成本高于收益；本期只保证"不静默"。
  • 无覆盖率数字：零依赖约束下未引入覆盖率工具，改用"每个 P0/P1 都有可在纯 Node 下跑的回归用例"作为替代门禁。
  • 无生产部署：这是本地单机工具，没有服务器与生产环境，部署环节不适用。
07 — 测验

自测（8 题）

Q1 选择manifest 里 blockCount=45、renderedBlocks=26，说明什么？
查看答案

A. 有 19 个块没产生独立内容，应结合 unsupportedTypes / degradedCount 判断是容器块还是真的没导出。B「全部成功」和 C「算错了」都不成立；D 忽略了并列统计的意义。

Q2 判断assets.missing 是空数组，就代表没有资源缺失。
查看答案

错。必须同时看 saved / total / skipped。更关键的是：v1.1 之前这个字段恒为 []，本身不可信。

Q3 选择单个附件 190MB，默认行为是？
查看答案

B：跳过并记入 assets.skipped、打印 ⚠ 告警，可用 --max-asset-bytes 放开。不是失败、更不是静默丢弃。

Q4 简答为什么探查阶段要传 null 而不是 []？
查看答案

null = 只探查：返回资源清单但不下载；[] = 什么都不做。原实现只在 chunkIndexes === null 时返回 assets 明细，传 [] 导致 probe.assets 恒为 undefined，进而 manifest.assets.missing 恒为 []。

Q5 判断单个块渲染抛异常会让整篇导出失败。
查看答案

错。v1.1 起 HTML 与 Markdown 两侧都有单块 try/catch，输出 ［渲染失败块：type / id］ 并记入 renderErrors，其余内容照常产出。

Q6 选择CDP send 的定时器泄漏，用户感知到的现象是？
查看答案

B：所有日志已经打印完，终端却不返回，要等最后一个 180 秒定时器到期才退出。

Q7 简答要验证一个含 190MB 附件的文档能完整导出，怎么做？
查看答案

node --max-old-space-size=2048 feishu-export.mjs <链接> --max-asset-bytes 209715200，然后核对 manifest.assets.saved === total、skipped 为空，且 assets/ 下文件字节数与源一致（实测 199754226 字节）。

Q8 判断engines.node: ">=20" 是安全的声明。
查看答案

错。全局 WebSocket 在 Node 22 才稳定；Node 20 需要 --experimental-websocket。v1.1 改为 >= 22 并在加载时探测给出提示。
